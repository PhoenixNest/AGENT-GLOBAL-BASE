## Proposed Preventive Changes — awaiting CEO approval

None of these is implemented. Each is a proposal; owners are assigned by module remit from the
crew roster and take effect only on approval.

| #   | Proposed change                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Owner                                                                                                      |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| (a) | **Reproduce the loss before choosing a fix.** On a scratch clone with a populated `_shared/models/`, replay the 2026-08-31 23:44–23:58 sequence: checkouts and merges across branches on both sides of commit `c8efa649`, then the three resets on `anu00/dev/thinking`. Record which operation, if any, empties the folder. If none does, the branch-switch hypothesis is rejected and the search moves to non-git actors in that window                                                                                                                       | Ravi Deshmukh (dev environment). Dr. Tomasz Wieczorek reviews the test design and the conclusion           |
| (b) | **Extend the `SessionStart` bootstrap check to the model cache.** `mcp-venv-bootstrap.py` covers a missing venv. Add a check that each required slug holds a top-level `config.json`, tokenizer files and a weights file, warning and re-provisioning when it does not. Fix the `provision_model.py` guard in the same change so that it tests for those files, since an empty subfolder currently makes it report a model as cached                                                                                                                            | Ravi Deshmukh (dependency and environment provisioning). Dr. Vance approves, as the hook is workspace-wide |
| (c) | **Relocate the shared model cache outside the repository tree**, addressed by an environment variable with a per-user default, so that no git operation on the working tree can reach it. This changes a contract shared by three consumers and is a cross-module architecture decision. Decide it after (a): if the loss has a non-git cause, relocation does not address it                                                                                                                                                                                   | Dr. Vance decides; Ravi Deshmukh executes                                                                  |
| (d) | **`health_check` must report a missing or failed model immediately.** `agent-memory` reported `loading` for hours over a folder that could never load; a file-presence test before the load attempt turns that into an immediate `failed`. `workspace-knowledge` reported `hybrid_qdrant` with no degradation reason while its fallback model was absent; a tier must not read as healthy when the fallback it depends on cannot load                                                                                                                           | Mei-Ling Zhao for `agent-memory`; Sofia Almeida for `workspace-knowledge`                                  |
| (e) | **Degraded keyword search must return nothing when nothing scores above zero.** The tier 3 path returned reflection records for "recipe for chocolate cake". A zero-score result presented as a match is worse than an empty result, because the caller cannot tell the two apart                                                                                                                                                                                                                                                                               | Mei-Ling Zhao; Sofia Almeida reviews the scoring floor                                                     |
| (f) | **Launch-lock handling.** A stale lock does not block a relaunch: `_acquire_lock()` clears any lock older than 60 s. Two gaps remain. Staleness is judged by file age only and the PID in the lock is never checked, so a consumer arriving within 60 s of a killed launcher waits up to 90 s for a service nobody is starting. And when the models are absent, each launch attempt holds the lock for its full wait with no signal that the launch cannot succeed. Proposed: check PID liveness, and have the launcher fail fast when a required slug is empty | Kwame Asante (harness: error boundary and recovery), with Connor O'Malley                                  |
